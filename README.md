# A Retrieval-Augmented Generation Framework for Knowledge Management Using Local Large Language Models

This project builds a private, local retrieval system for scientific papers. It uses three locally served language models (Mixtral-8×7B, Qwen3-VL-8B, and Llama-3.1-8B) to generate abstracts for arXiv papers, and Llama-3.1-8B performed best, so it powers the knowledge base. Abstracts are stored in a vector database and searched semantically, so documents can be found without sending them to cloud services.

## Overview

The general workflow is:

1.  Load a dataset of paper records from a metadata file.
2.  Extract the categories to keep
3.  Validate required fields such as `paper_id`, `title`, `abstract`, and `body`.
4.  Pass through the filtering conditions and keep the first 200 obtained papers
5.  Load configurations and set the path
6.  Load CSV and index abstracts.
7.  Initialize local models.
8.  Generate a test set.
9.  Run a retrieval pipeline
10. Generate answers.
11. Run RAGAS evaluation.
12. Validate the questions.
13. Finally, export metrics to CSV.


This codebase is designed for experimentation on academic abstract generation and model comparison using local LLMs.

## Project structure

### Core model runners
- `run_qwen.py` - main generation pipeline for the Qwen model runner.
- `run_llama.py` - wrapper script that configures the LLaMA model and runs the generation pipeline.
- `run_mixtral.py` - wrapper script that configures the Mixtral model and runs the same abstract-generation flow.

### Core implementation files
- `lm_client.py` - OpenAI-compatible client wrapper for LM Studio requests.
- `summarizer.py` - generation prompting and map-reduce summary merging logic.
- `data_io.py` - input/output CSV utilities, validation, and run logging.
- `evaluate.py` - lightweight evaluation stub file for BLEU/ROUGE/BERTScore placeholders.
- `evaluate_abstracts.py` - full evaluation script that computes BLEU, ROUGE-1, ROUGE-L, and BERTScore against gold abstracts.
- `abstracts_stats.py` - per-paper statistics script for generated abstracts and scoring by article.
- `avg_word_length.py` - utility to compute average generated abstract length.
- `prep_arxiv_csml_pairs.py` and `prep_arxiv_csml_pairs_S2ORC.py` - data preparation scripts for building sampled paper datasets.
- `RAGAS_Pipeline.ipynb` - implements and reports RAGAS evaluation metrics: faithfulness, answer correctness, context precision, context recall.

### Data and outputs
- `data/` - sample CSV datasets and generated output files.
- `stats/` - summary statistics and experiment result files.
- `config-presets/` - preset files used by model configurations.
- `runs/` - run logs generated by the pipeline.

### Additional analysis scripts
- `abstracts_stats.py` and `evaluate_abstracts.py` are the main scripts for model evaluation.
- `avg_word_length.py` helps monitor output length consistency.
- `evaluate.py` is a placeholder or simpler metric stub for early experimentation.

## Requirements

- Python 3.10+
- A local LM Studio server running with a model loaded
- Required Python libraries from `requirements.txt`

Install dependencies:

```bash
pip install -r requirements.txt
```

## Setup

1. Start LM Studio on your machine.
2. Load a compatible model such as Mixtral, Qwen or LLaMA.
3. Ensure the local server is exposed through the OpenAI-compatible endpoint:

```text
http://localhost:1234/v1
```

4. Prepare a CSV dataset containing at least these columns:

- `paper_id`
- `title`
- `abstract`
- `body`

## Running the pipeline

### Qwen model

```bash
python run_qwen.py --in data/arxiv_csml_body_abstract.csv --out data/output.csv
```

You can override the model and base URL if needed:

```bash
python run_qwen.py --in data/arxiv_csml_body_abstract.csv --out data/output.csv --base_url http://localhost:1234/v1 --model qwen3-vl-8b-instruct
```

### LLaMA model

```bash
python run_llama.py --in data/arxiv_csml_body_abstract.csv --out data/output.csv
```

The LLaMA runner sets the model name internally to `meta-llama-3.1-8b-instruct` unless changed in the script.

### Mixtral model

```bash
python run_mixtral.py --in data/arxiv_csml_body_abstract.csv --out data/output.csv
```

The Mixtral runner sets the model name internally to `Mixtral_Instruct_8x7b` unless changed in the script. This is the default local model configuration used for the Mixtral pipeline in this project.

## Implementation details

### Client layer
`lm_client.py` defines a thin wrapper around the OpenAI Python SDK. It creates a client pointed at the LM Studio endpoint and sends chat-completion requests with a system prompt instructing the model to write a formal academic abstract.

### Summarization
`summarizer.py` handles long-document processing:

This approach helps keep prompts within model context limits while preserving the main ideas from the document.

### Data handling
`data_io.py` reads input CSVs, validates the required columns, writes generated abstracts to a CSV output, and logs run status in the `runs/` folder.

## Notes

- The project is designed for local experimentation and research workflows, not a production API service.
- The project compares three local models: Qwen, LLaMA, and Mixtral.
- Long documents may require tuning of chunk sizes and prompts to improve quality.
- Evaluation scripts are included to measure generated abstracts against gold references using BLEU, ROUGE, and BERTScore.

## Common usage pattern

```bash
python run_qwen.py --in data/arxiv_csml_body_abstract.csv --out data/output.csv --limit 50
```

This limits the number of papers processed, which is useful for testing prompt quality or validating the pipeline on a smaller sample before running the full dataset.
